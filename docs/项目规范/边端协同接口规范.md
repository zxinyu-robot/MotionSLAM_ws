---

## 0. 原则

1. **JSON 仅用于边端边界**（`:9879` 下行、`:9880` 上行反馈）。组织方式对齐大疆上云 API：**信封 + 物模型 data 块**，不是扁平 waypoint 列表。
2. **端内** ingress 解析后使用 ROS 话题/黑板；BT↔PCT↔SCAN **不传 JSON 字符串**。
3. 边端不下发 `/cmd_vel`；TTL / session / `context_generation` / robot×scene×mode 校验失败 → REJECT + 停车。
4. 世界模型必须输出 **行为模式**（谁在什么场景用哪套策略跑哪些技能），不得只给一个点、也不得直控机器人。
5. 上行 `events` 是给 **世界空间再规划** 用的（OS2 闭环）；`world_fragments` 只是记忆 **引用**，不是共享记忆查询 API。MCP / 技能商店不是本契约。
6. 配置真相：[edge_uplink.yaml](../../src/motionslam_bringup/config/edge_uplink.yaml)

## 2. 物模型信封（主契约）

实现：`behavior_mode.py` · 入口：`directive_receiver_node` · 执行：`command_executor_node`  
schema：`motionslam.thing_envelope.v1`

对齐大疆物模型 TSL 的四维（**是什么 / 有什么状态 / 能被调用什么 / 会上报什么**），并补上策略、模型、世界片段三块，使一次任务可审计。

| 大疆 | 本仓库 `data` 块 | 回答的问题 |
|------|------------------|------------|
| `profile` | **profile** | 所用机器人 |
| `properties` | **properties** | 所在场景 + 模式生命周期 |
| `services` | **services** | 所用动作（技能，不是速度） |
| （业务扩展） | **policy** | 所参考的行为策略 |
| （业务扩展） | **models** | 所用的模型 |
| `events` | **events** | 所出现的异常行为日志 |
| osd 载荷引用 | **world_fragments** | 所生产的世界片段数据 |

外层信封对齐大疆 services/events 公共头：

| 字段 | 大疆 | 本仓库 |
|------|------|--------|
| `tid` | 事务 ID | = `command_id` |
| `bid` | 业务 ID | = `session_id` |
| `timestamp` | 毫秒或纳秒 | ns（>1e15）或 ms |
| `method` | 服务/事件名 | 下行 `behavior_mode.execute`；上行 `behavior_mode.progress` / `behavior_mode.event` |
| `need_reply` | 事件是否需云端回 | 仅上行；EXCEPTION 时为 1 |
| `data` | 方法载荷 | 下列七块 |

**禁止**出现在任何块中：`cmd_vel`、`/cmd_vel`、`twist`、`/initial_path`、`/motion/command`。Nav2 控制器名不得当作 `method` 或 `skill`。

### 2.1 下行 services（:9879，`method=behavior_mode.execute`）

必填：`profile`、`properties`（含场景）、`services.actions`、`policy`、`models`。  
`events` 必须缺省或空（异常日志由端侧上行，模型不得在 services 里预填）。  
`world_fragments` 可选，仅允许 **引用**（`layer_id` + `ref`/`digest`/`uri`），禁止内联点云。

  "tid": "uuid",
  "bid": "demo_live",
  "timestamp": 0,
  "method": "behavior_mode.execute",
  "data": {
    "profile": {
      "sn": "go2_001",
      "platform": "unitree_go2_edu",
      "domain": "legged",
      "type": "go2",
      "thing_version": "1.0.0",
      "capability_tags": ["Navigate", "ReturnHome", "RecoverGlass"]
    },

      "semantic_tags": ["turn_right_at_next_junction"],
      "language_query": "前面路口右转",
      "map_id": "demo_live_map",
      "floor_id": "floor_01",
      "frame_id": "world",
      "context_generation": 42,
      "mode_state": "INIT"
    },
    "services": {
      "actions": [
        {
          "skill": "Navigate",
          "goal": {
            "type": "semantic_ref",
            "ref": "next_intersection_exit_right",
            "x": 2.0,
            "y": 0.5,

          }

    "policy": {
      "mode_id": "navigate_intersection_cautious",

      "policy_ref": "policydb://scene/intersection/cautious",
      "lifecycle_policy": {
        "on_link_lost": "ReturnHome",

Demo 1 允许的枚举（未知即拒）：

| 字段 | 允许值 |
|------|--------|
| `platform` | `unitree_go2_edu`、`unitree_go2` |
| `scene_type` | `office_corridor`、`intersection`、`glass_facade`；`elevator_lobby` **预留 Demo 2** |
| `mode_id` | `navigate_office`、`navigate_intersection_cautious`、`navigate_glass_aware`、`return_home_on_link_lost`、`explore_frontier` |
| `skill` | `Navigate`、`ReturnHome`、`RecoverGlass`、`ExploreFrontier` |
| `goal.type` | `waypoint`；`semantic_ref` **必须同时带 xyz**（本轮端侧不解算语义，否则 `REJECT_UNRESOLVED_GOAL`） |

`language_query` 只是场景旁注；语音「路口右转」由边侧模型译成 `scene_type` + `semantic_tags` + 技能，**不**进度量内核。

### 2.2 模式生命周期

与栈 `/demo/lifecycle/state`、BT `ExecPhase` **分名**：

```text
INIT →（ACCEPT）ARMED → ACTIVE（= MONITOR）→ TERMINATED
                         ↘ EXCEPTION →（recover）ACTIVE
                                     → TERMINATED
```

| 状态 | 含义 | 上行 |
|------|------|------|
| INIT | 收到 execute，校验中 | `mode_init_received`（可选） |
| ARMED | 身份与栈就绪 | `task_accepted` + `mode_state=ARMED` |
| ACTIVE | 技能执行中 | `search_navigate` / `pct_path_received` + `mode_state=ACTIVE` |
| EXCEPTION | 偏离契约 | `mode_exception`，`reason` ∈ `plan_fail` / `stuck` / `glass_trap` / `link_lost` |
| TERMINATED | 释放 | `mode_succeeded` / `task_rejected` / `mode_failed` |

`lifecycle_policy` 只声明异常时切哪条技能；真机触发仍走现有 BT（本轮不改 PCT/SCAN）。

### 2.3 上行 events（:9880）

`method=behavior_mode.progress` 时，`data` 仍带 **同一套七块的快照**（profile / properties / policy / models），并填：

- **events**：异常与进度日志（EXCEPTION 时必填非空）
- **world_fragments**：本次生产的世界片段 **引用**（Token / 子图 / RGB / 策略摘要），带 `layer_id` + `context_generation` + `ref` 或 `digest`，禁止内联几何

现有 `motionslam.execution_feedback.v1` 继续作为 TCP 载荷；新增可选字段 `mode_id`、`mode_state`、`scene_type`、`events`、`world_fragments`。完整物模型上行可用 `build_progress_envelope()`。

事件名（实现）：`task_accepted`、`subgoal_dispatched`、`pct_path_received`、`subgoal_reached`、`task_rejected`、`plan_fail_hold`、`return_home_started` 等。代码 **没有** `pct_nav_started`。

`events.reason` 稳定枚举须对齐 OS1（`plan_fail` / `stuck` / `glass_trap` / `link_lost`）。世界模型消费这些码并重发 `behavior_mode.execute` 属于规划 **RT-2**，本规范只保证字段可解析；端侧不在 ingress 内做大模型纠错。

三类记忆不进控制 JSON：

| 记忆 | 生产 | 查询（世界空间，RT-3） |
|------|------|------------------------|
| 空间 | Token / 子图 / RGB 的 `world_fragments` 引用 + `context_generation` | 按 `bid` + 代数取片段 |
| 时间 | `mode_state` 时间线与 `events[]` | 按 `tid` 拉监控树（RT-4） |
| 本体 | `profile` + PolicyDB 策略摘要 | 按 `sn` / `platform` / `mode_id` |

### 2.4 兼容：SemanticDirective / ActionGroup

| schema | 何时用 |
|--------|--------|
| `motionslam.thing_envelope.v1` | **边端主契约**；缺三元组即拒 |
| `motionslam.action_group.v1` | 旧 OBJNAV；`require_behavior_mode=false` 时仍转发 |
| `motionslam.semantic_directive.v1` | frontier 偏置；不是行为模式 |

`require_behavior_mode:=true` 时，纯 ActionGroup → `REJECT_MISSING_BEHAVIOR_MODE`。板载 `mission_mode:=demo_waypoints` **不经** JSON。

发布：thing envelope 与 ActionGroup 均到 `/semantic/action_group` → `command_executor`（需 `with_semantic_objnav`）→ BT。

### 2.5 拒绝码（节选）

| 码 | 含义 |
|----|------|
| REJECT_SCHEMA | schema 不匹配 |
| REJECT_SESSION / REJECT_MISSING_BID | session / bid 不一致或缺失 |
| REJECT_MISSING_COMMAND_ID | 无 tid/command_id |
| REJECT_MISSING_ROBOT / REJECT_ROBOT_MISMATCH | 无机器人画像或与本机不符 |
| REJECT_MISSING_SCENE / REJECT_SCENE_TYPE | 无场景或非法 scene_type |
| REJECT_MISSING_BEHAVIOR_MODE / REJECT_MODE_UNKNOWN | 无模式或非法 mode_id |
| REJECT_MISSING_ACTIONS / REJECT_SKILL_UNSUPPORTED | 无动作或技能不在 capability |
| REJECT_MISSING_MODELS | 未声明所用模型 |
| REJECT_FORBIDDEN_CONTROL | 含速度/折线直控 |
| REJECT_EVENTS_ON_SERVICE | 下行 services 夹带异常日志 |
| REJECT_UNRESOLVED_GOAL | semantic_ref 无 xyz |
| REJECT_FRAGMENT_*_INLINE_PAYLOAD | 世界片段内联几何 |
| REJECT_STAGE_* | 旧 ActionGroup stage/waypoint 非法 |

## 3. 端内 ROS 对照（非 JSON）

与 `demo_scan_stack.launch.py` + `demo_scan_bt_orchestrator.py` 一致。

| 阶段 | 话题/接口 |
|------|-----------|
| ingress → BT | `/semantic/action_group`、`/semantic/directive` |
| frontier → BT | `/demo/mission/frontier_snapshot` |
| BT → PCT | `/goal_pose`；服务 `/build_tomogram`（预热）；订阅 `/global_path`（**stamp 必须等于请求**） |
| BT → SCAN（PCT 开，默认） | `/initial_path`（`scan_track_pct_path=true`，`navi_mode=3`） |
| BT → SCAN（PCT 关） | `move_base_simple/goal`（`navi_mode=1`） |
| 返航 | 同一 `/initial_path`（面包屑倒序；不调 PCT） |
| 玻璃/BEV 虚拟障碍 | `/perception/virtual_obstacles`、`/perception/virtual_obstacles_bev` → `/perception/scan_cloud_fused` |
| 上行心跳 | `execution_feedback` → `/demo/mission/uplink_ok`；丢失可触发返航 |
| SCAN → 跟踪 | `/planning/bspline` |

PCT 空路径时 `pct_fallback_direct` 默认 false：不发直线 `/initial_path`，等 BT 恢复。

板载任务默认 `mission_mode:=demo_waypoints`（yaml 航点），不经边端 JSON。
