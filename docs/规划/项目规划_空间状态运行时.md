# 项目规划：空间状态与任务运行时

> **版本**：2026-10-24 · **目标规划，未验收**。本文件是当前目标与后续工作入口，不把目标描述为已实现。

> 架构：[端侧系统架构](../架构/架构_端侧系统架构.md) · 协议：[边端协同接口规范](../项目规范/边端协同接口规范.md) · 真机证据：[测试记录](../测试验收/测试记录.md)

## 1. 项目定位

建立面向足式机器人的 Linux 原生空间状态与任务执行运行时，贯通 **状态 → 决策 → 动作 → 新状态**。目标不是另造 SLAM、规划器或 Nav2，而是将空间状态、上游任务意图、设备侧行为运行时和安全执行组织成可校验、可恢复、可追溯的闭环。

现有 Super-LIO → PCT C++ → BT → SCAN → forwarder/Sport 是当前工程实现锚点；实际能力和验收日期以原始集成仓最新源码、日志与真机记录为准。**整个改造期间现有 ROS 2 overlay 冻结、不动**：不改 workspace、包、依赖、colcon 配置、构建/环境脚本或 overlay 内源码，也不迁移/重建该 overlay。Linux 原生运行时在 overlay 外独立演进，通过已有边界协作。Nav2 插件只允许独立实验分支，且同样不得修改冻结的 overlay。

## 2. 固定的三个接口

| 接口 | 职责 | 必要语义 |
|---|---|---|
| **Spatial Asset API** | 查询、订阅版本、应用增量、请求/恢复快照 | 稳定 asset ID、revision、frame、digest、时间、来源与依赖 |
| **Task Intent API** | 提交、取消、暂停/恢复、调整优先级、校验能力 | 任务目标、受能力表约束的技能序列、区域/导航约束、前置条件和资产引用 |
| **Execution Feedback API** | 接受/拒绝、当前技能、进度、异常、结果、重规划事件 | task ID 关联、稳定状态/原因码、可回放事件顺序 |

三个领域 API 独立演进，通过 task ID 和空间资产引用关联；协议不暴露 BT 树、节点或黑板，也不绑定某种 BT、Token codec、传输或机器人控制框架。

## 3. Task Intent 与设备侧运行时

**当前代码进度（2026-10-24）**：新增 `runtime/task_runtime/` 作为 Linux 原生 C++20 lifecycle core 初始骨架，覆盖单活动任务、技能顺序进度、暂停/恢复/取消/失败和安全互锁，并有独立无 ROS 2 单元测试源码。它尚未接入 Thin Harness 或现有 BT/PCT/SCAN；deadline、priority、preemptible 目前只是意图字段，不代表已实现调度策略。C++ 构建/测试尚未在本 VFS 环境执行。

上游模型负责全局任务目标/分解、声明式技能顺序及依赖、作业区域、沿途导航约束、行为策略意图、优先级、期限和抢占属性。空间引用包含 `asset_id/revision/context_generation/frame_id`。仅要求到达区域时，路径由设备规划；要求严格通过时，显式给必经航点或路径走廊。

Task Intent 是受 schema 和设备能力表约束的技能级意图，不是 BT XML 或任意树序列化。设备侧 Thin Harness 负责解析、权限/能力校验、资产版本和前置条件检查、任务映射及生命周期管理，不重复上层任务规划。

本地 BT/状态机接收已校验技能和约束，负责技能内部流程、运行时条件、实时感知驱动的动态分支、局部避障/重规划、暂停/重试/恢复和技能生命周期。实时控制器闭环及设备硬安全机制拥有最高执行优先级；急停、碰撞保护、限速、断链安全行为不得被上层策略覆盖。

### 运行时热插拔

热插拔是目标能力，当前未实现。每个模块须声明 ABI/schema 版本、能力、输入输出类型、frame/资产兼容范围、资源预算、健康状态及状态迁移能力。注册、校验、暂存、激活、排空、移除和回滚均需可观测。

优先支持可无状态替换的 codec/传输 adapter；资产管理或规划实现切换需确认快照可迁移。状态估计器、规划器或控制器切换不得默认在运动中直接进行：先暂停/安全停、排空依赖旧模块的任务，验证新模块与资产/代数兼容，再原子切换并可回滚。物理传感器掉线或重新接入视为能力/健康状态变化，不能自动复活旧任务。

## 4. 多维空间状态、资产图与哈希索引

不把位姿图、planner 体素图、代价地图、语义目标信息和可通行性层析图合并为一种数据结构。每类保留适合生产者/消费者的 typed payload，通过**版本化空间资产图**关联：

- 节点表示资产的一个明确版本，记录 `asset_id/layer/revision/session/context_generation/frame_id/timestamp/bounds/resolution/digest/codec/confidence/source`。
- 类型化边表达 `derived_from`、`aligned_by`、`projects_from`、`constrained_by`、`consumed_by` 等来源和依赖。空间邻接关系与生命周期依赖关系不要混成同一条边。
- 哈希表/空间哈希用于热路径索引，例如 asset key → manifest、`(i,j,k)` → voxel block、landmark ID → pose graph node、`(frame,timestamp)` → transform。内部 hash 值不作为跨进程 ID；跨节点使用稳定 ID 和确定性 digest。
- 树仅作 robot/session/map/layer 的目录、权限和生命周期视图；权威关联模型为有类型的图，不要求首版使用图数据库。

`frame_id` 不能仅靠重命名统一。保留 `world/map/odom/base` 的真实语义，通过带时间戳、来源和有效期的 transform graph 完成坐标变换。

每个决策周期形成不可变 `DecisionSnapshot`/manifest，引用当时使用的位姿、位姿图、体素、costmap、语义层、通行性层和 transform 版本。各资产 revision 可以不同，但来源、时间、变换和依赖必须构成一致性切面；缺变换、过期或受污染状态不能进入规划。首版以 manifest + 本地索引实现，不引入分布式图数据库作为前置条件。

## 5. 空间—任务版本闭环

空间资产持续上行，不与任务更新一一对应。任务运行中发现区域变化时，先更新本地资产，由 BT 在当前任务约束内进行局部避障、暂停或允许的恢复；若目标可达、区域/走廊/前置条件仍有效，则在本地最新 snapshot 上重验证或重规划后继续，无须等待云端。

只有目标不可达、任务约束/前置条件失效或全局任务顺序受影响时，Execution Feedback 才上报决策事件并触发上层重规划。revision 43→45 必须检查差分与任务区域/走廊/约束的关系，不能只看数字；设备处于 revision 40 而任务要求 43 时先按游标补增量，无法重建基线就请求快照并暂停执行。

## 6. 状态估计失效与安全降级

定义 `NORMAL_3D → DEGRADED_2D → RELOCALIZING → VERIFYING → RESTORED`；门限不满足、来源不可信或超时则进入 `HOLD`。3D 观测器污染/失效时撤销旧执行授权，取消旧规划，隔离污染资产并拒绝旧 generation 输出，同时上报健康/故障状态。

仅当 2D 位姿、局部障碍观测、地图走廊和运动约束均可信时才允许受限、限速、限域的 `DEGRADED_2D`；否则 HOLD。2D AMCL 只恢复 XY/yaw，不单独证明足式 3D 高度/姿态有效。恢复 3D 前还需连续健康观测、TF/frame 一致、新 context generation、资产重建/对齐及新路径验证。当前仓库快照未证明 AMCL 已集成，此能力须列为待设计/实现/真机验收。

## 7. 通信与 Token 编码

通信基座为 **SHM + DDS + UDP**：SHM 服务同机大数据和离线资产日志；DDS 服务发现、控制/心跳、健康状态、任务反馈、资产目录和同步游标；专用 UDP 承载跨主机大载荷分片/增量。UDP 应用层须处理 seq/digest、分片校验、TTL、乱序/丢包、补传、快照恢复和背压。DDS 可独立于 ROS 2 使用；DDS/RTPS 可能以 UDP 为底层承载，须与专用大载荷 UDP 通道区分。

控制/心跳/位姿优先，子图和层析图按需增量同步，全局点云限速或延后。断网不阻塞本地规划；SHM/append log 是离线数据真相。

Token 只在资产身份/引用或特定 payload codec 有明确收益时采用。资产 manifest 与关系引用先稳定；不同数据类型保留不同 codec，不把所有地图压成无法还原 frame、来源和版本的单一向量，也不把空间 Token 用作下行技能 ID。现有 MSTOK 是 JSON meta + 栅格字节封帧，不等于离散 iVox Token。

## 8. 地图淘汰与 ESN

地图淘汰分内存压力与空间/时间过期两条策略，依据 RSS、滑窗、资产依赖和安全约束执行。Far-Planner 关键点投票与高度通道作为算法参考；帧数阈值、关联距离用离线回放扫描，评估误关联、静态信息保留、动态污染、路径安全和峰值内存后再确定。

ESN 只作为运动响应短时预测/偏差检测旁路：输出预测、残差和适用性，不输出控制，不独立决定安全状态。先与恒速/线性/Kalman baseline 做离线比较，再考虑 shadow mode。DAgger、学生模型和端侧大模型不进入当前版本。

玻璃类别专用策略、mode、skill 和恢复分支全部移出当前版本，留给后续上游决策模型；端侧只保留类别无关的几何障碍与硬安全规则。

## 9. 实施门禁

1. **基线**：核验 GitLab `origin/dev`、工作区/子模块改动及现有 CI；保留用户改动，不 reset/force push。Nav2 实验另开分支。
2. **BT runtime**：Linux 原生构建；验证唯一执行权、任务生命周期、动态本地分支、暂停/恢复、故障隔离和反馈。
3. **资产一致性**：验证多 frame transform、哈希冲突后完整键校验、snapshot manifest、资产差分/快照重建和淘汰依赖。
4. **Task/API 闭环**：验证能力拒绝、重复 task ID、抢占、区域/禁区/waypoint/corridor、deadline、资产版本兼容、局部变化继续与重大变化 REPLAN。
5. **安全降级**：验证 DEGRADED_2D 条件、HOLD、AMCL 未收敛/收敛、可信高度姿态和重定位后的新代状态恢复。
6. **通信与性能**：CI 只做 Linux 原生核心 build/test、协议回放、断网/乱序/丢包/重连和 P95/P99 tick/端到端时延、CPU/RSS/带宽采样；不构建、source、迁移或修改冻结的 ROS 2 overlay。云端 CI 不替代真机验收，不声称未验证的硬实时。
7. **证据**：所有通过项关联提交、配置、日志/回放、日期和硬件条件；目标不等于已实现。
