# 符号空间契约（任务意图 / 生命周期）

> 目标架构"空间状态 → 任务意图 → 安全动作 → 新状态"中符号空间的接口契约。
> 实现：`runtime/task_runtime`（C++ 权威定义）+
> `src/motionslam_bringup/scripts/task_runtime_adapter.py`（Python 同契约镜像，
> 供 thin_harness / 编排层先行接入）+ `task_intent.py`（入口校验）。

## TaskIntent（任务意图）

| 字段 | 类型 | 说明 |
|---|---|---|
| task_id | string | 全局唯一，重复提交返回 `duplicate_task_id` |
| task_type | string | 如 `navigate`、`return_home` |
| goal | string | 目标描述（区域 / 语义目标） |
| target_area | string | 目标区域标识（可选） |
| world_reference | WorldReference | 世界空间资产引用：asset_id / revision / context_generation / frame_id |
| skill_sequence | SkillCall[] | 有序技能调用表（skill + target） |
| execution | ExecutionPolicy | priority / deadline_ns / preemptible |

校验规则（入口由 `task_intent.py` + `TaskRuntimeAdapter.submit` 双重执行）：
- task_id / task_type / goal 必填非空 → 否则 `invalid_intent`
- task_id 不可复用（终态后依然占用）→ `duplicate_task_id`
- 单活动任务：有非终态任务时新提交 → `task_already_active`
- SafetyMode=HOLD 时拒绝新提交 → `safety_interlock`

## 生命周期状态机

```
accepted ──start──▶ running ──┬─ complete 全部技能 ─▶ succeeded
    ▲                         ├─ fail(reason) ─────▶ failed
    │                         ├─ cancel() ─────────▶ canceled
    │                         ├─ pause() ──▶ paused ──resume()──▶ running
    │                         └─ safety HOLD ─▶ holding ─(退出 HOLD)─▶ running
```

- 终态 = succeeded / failed / canceled，终态后允许新任务
- SafetyMode：normal / degraded / hold；HOLD 对运行中任务置 holding，恢复后回到 running
- 事件流（RuntimeEvent）：task_accepted / task_started / skill_started /
  skill_completed / task_paused / task_resumed / safety_hold /
  task_succeeded / task_failed / task_canceled —— 即"新状态"回写世界空间的载体
