# 符号空间契约（任务意图 / 生命周期）

> 目标架构"空间状态 → 任务意图 → 安全动作 → 新状态"中符号空间的接口契约。
>
> 三空间语义：世界空间产出**空间状态**（几何观测事实）；
> 符号空间受**语义价值信息约束**（任务意图=语义价值的表达，
> 决策模型/ESN 在此空间处理语义信息）；
> 度量空间受**几何约束**（安全动作=几何可行性边界内的执行，
> SCAN/执行层保证），执行结果回写为新空间状态。
> 项目面向工程落地，权威实现在 C++（`runtime/task_runtime`）。
> 实现：`runtime/task_runtime`（C++ 权威定义）+
> `src/motionslam_bringup/scripts/task_runtime_adapter.py`（Python 同契约镜像，
> 供 thin_harness / 编排层先行接入）+ `task_intent.py`（入口校验）。

## TaskIntent（任务意图）

| 字段 | 类型 | 说明 |
|---|---|---|
| task_id | string | 全局唯一，重复提交返回 `duplicate_task_id` |
| task_type | string | 如 `navigate`、`return_home` |
| goal | string | 目标描述（区域 / 语义目标） |
| target_area | string | 目标区域标识（可选） |
| world_reference | WorldReference | 世界空间资产引用：asset_id / revision / context_generation / frame_id |
| skill_sequence | SkillCall[] | 有序技能调用表（skill + target） |
| execution | ExecutionPolicy | priority / deadline_ns / preemptible |

校验规则（入口由 `task_intent.py` + `TaskRuntimeAdapter.submit` 双重执行）：
- task_id / task_type / goal 必填非空 → 否则 `invalid_intent`
- task_id 不可复用（终态后依然占用）→ `duplicate_task_id`
- 单活动任务：有非终态任务时新提交 → `task_already_active`
- SafetyMode=HOLD 时拒绝新提交 → `safety_interlock`

## 生命周期状态机

```
accepted ──start──▶ running ──┬─ complete 全部技能 ─▶ succeeded
    ▲                         ├─ fail(reason) ─────▶ failed
    │                         ├─ cancel() ─────────▶ canceled
    │                         ├─ pause() ──▶ paused ──resume()──▶ running
    │                         └─ safety HOLD ─▶ holding ─(退出 HOLD)─▶ running
```

- 终态 = succeeded / failed / canceled，终态后允许新任务
- SafetyMode：normal / degraded / hold；HOLD 对运行中任务置 holding，恢复后回到 running
- 事件流（RuntimeEvent）：task_accepted / task_started / skill_started /
  skill_completed / task_paused / task_resumed / safety_hold /
  task_succeeded / task_failed / task_canceled —— 即"新状态"回写世界空间的载体

## 五层职责边界（逻辑分层，不对应进程数）

| 层 | 组件 | 负责 | 不负责 |
|---|---|---|---|
| 任务层 | Thin Harness + BT（终态：决策模型 + ESN） | 接收任务意图、维护任务状态、管理全局目标、选择局部子目标、超时与恢复 | 几何可行性、轨迹生成、速度计算 |
| 规划层 | PCT + SCAN | PCT：基于可通行性表示的全局可行路径；SCAN：按局部空间、机器人状态、局部参考生成 B 样条局部轨迹 | 任务推进、到达判定、设备安全 |
| 控制层 | closed_loop | 按控制周期跟踪有效轨迹，输出线速度/角速度；产出跟踪误差、执行状态、故障反馈 | 规划、任务决策、设备限幅 |
| 设备层 | go2_adapter（`CmdVelForwarder`）+ Sport API；云端由 vkernel 模拟 Sport | 速度接口、限幅（vx/vy/vyaw）、看门狗 400ms、StopMove 安全停止、底层执行 | 空间状态生产、任务判定 |
| 状态层 | Super-LIO + 空间状态管理 | 统一位姿、点云、地图/可通行性；管理 stamp、frame_id、有效性、更新状态 | 任务决策、运动执行 |

状态层对任务/规划/控制层是**持续反馈**（不是单向流水线）；执行链
（控制层 → 任务层）返回**结果**，两者共同构成任务级闭环。安全停止在设备层
独立具备，不依赖任务层响应。

## 跨空间数据契约（对应 README 时序图）

时序图 `docs/media/state_flow_seq.png` 中的接口约定。✅=当前代码已有，📝=契约已定、待实现。

| 接口 | 方向 | 必含字段 | 现状 |
|---|---|---|---|
| GoalRequest | Thin Harness → BT | task_id, action_type, target_pose, target_frame, position_tolerance, timeout | 📝（当前 TaskIntent 只带坐标目标） |
| 空间状态 | Super-LIO/状态 Hub → BT 黑板 / PCT / SCAN | frame_id, stamp, 位姿/速度, 定位有效性（`/lio/relocation/*`、`/lio/backend/pgo_state`） | ✅ odom/点云/定位状态；📝 统一质量字段 |
| PlanResult（全局） | PCT → BT | status, plan_id, `/global_path`, failure_code | 📝（当前只回 Path，失败靠超时判定） |
| 局部参考 | BT → SCAN | `/initial_path`（前视截取的全局路径段 + 共线抽稀）, frame, plan_id, subgoal_idx | ✅ 路径段；📝 版本字段 |
| 局部轨迹 | SCAN → closed_loop | `/planning/bspline`（traj_id, start_time, frame） | ✅ |
| 速度指令 | closed_loop（控制层）→ go2_adapter（设备层）→ Sport API | vx, vy, ωz；限幅 + 看门狗 400ms 超时 StopMove | ✅（`CmdVelForwarder`，独立于 BT 的失效保护） |
| ExecStatus | closed_loop/SCAN → BT | execution_state, failure_code, tracking_error, goal_reached, trajectory_valid, traj_id | 📝（当前 BT 以 bspline 心跳 + 位姿进展 + stuck_timeout 近似） |
| task_terminal | BT → Thin Harness | state∈{succeeded, failed, canceled}, reason | ✅ |

判定规则：
- 子目标到达 = `|pose − subgoal| ≤ subgoal_reach_m`（且速度稳定 📝），不是"收到新 odom"；中间子目标到达回到下一子目标，仅最终目标满足终止条件才 `succeeded`。
- 失败分支：PlanResult 非 OK / 无进展超过 `stuck_timeout_s` / 定位失效 → 停止旧轨迹 → 重试·重规划·恢复·终止，不得无限等待。
- 版本链 `task_id → plan_id → traj_id`：规划更新或定位重置后旧版本数据作废，控制器不得继续跟踪。
- 执行三事件区分：速度指令被接受 ≠ 机器人实际运动 ≠ 到达目标。
